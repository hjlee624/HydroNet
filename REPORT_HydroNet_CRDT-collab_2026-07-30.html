HydroNet 팀 협업(CRDT) 전환 — 종합 보고서

사내 LAN에서 여러 작업자가 마일스톤 공정표를 실시간 공동 편집 — CRDT · DB · 프론트 개조 방안 (온프레미스 · 오프라인 · 자체호스팅 우선)

작성일 2026-07-30방법 웹 리서치 + 코드베이스 매핑 + 적대적 검증권장 CRDT Yjs단계 P0–P5

총평 Executive Summary

HydroNet은 이미 CRDT 전환에 유리한 골격을 갖췄다: (1) 모든 쓰기가 store.ts의 단일 commit() 관문을 통과하고, (2) CPM 계산(computeSchedule/applyCascade/reschedule)이 순수 함수로 입력값과 완전히 분리돼 있으며 어디에도 파생값(es/ef/critical)을 진실로 저장하지 않는다. 따라서 전환의 본질은 "전체-스냅샷 파이프라인(commit·past/future·전체 PUT)을 요소 단위 op로 바꾸는 것"이며, 렌더 레이어(SVG·zustand 셀렉터)는 그대로 두는 것이 목표다.

권고 스택은 온프레·오프라인·자체호스팅·단일 HTML(file://)·Electron 상성을 최우선으로 하여 Yjs로 확정한다. Yjs는 순수 JS·gzip ~18-20KB·WASM 없음이라 vite-plugin-singlefile 단일 HTML에 인라인 가능하고, y-indexeddb만으로 provider 없이 오프라인 영속이 되며, MIT 라이선스에 Hocuspocus(onAuthenticate·SQLite/DB 영속) 자체호스팅 서버와 Y.UndoManager가 이미 검증된 조각으로 존재한다. Automerge 2.x(WASM 604KB, parse 1.8s, offline 병합 OOM 이력)와 Loro(WASM 399KB)는 배포 형태 때문에 탈락하되, Loro는 tasks row/parentId 재정렬 정확성이 실측 병목으로 판명될 때만 2순위 승격한다(MovableList·Movable Tree가 도메인에 1:1).

두 개의 진짜 함정: (A) Task.row 재정렬·parentId 세부공정 재부모화가 Yjs의 'move 부재' 직격 지점 → Y.Array 인덱스 순서 대신 fractional-index 소수 정렬키 + Y.Map LWW로 모델링(delete+insert 금지). (B) 멀티시트의 '활성 시트만 최상위 + swap' 구조는 CRDT 궁합이 나쁨 → 전 시트를 Y.Doc에 상주시키고 활성 시트는 로컬 뷰 포인터로만 관리.

로드아웃은 무인증→인증, 파일→DB, 단일→협업을 점진적으로: 0(경계 명문화, 이미 완료)→1(로컬 Y.Doc화+y-indexeddb, provider 없음)→2(Y.UndoManager)→3(Hocuspocus 서버 동기+인증)→4(awareness 프레즌스)→5(배포·호환 마감, LWW PUT 제거). 각 단계는 기존 검증 게이트(build=tsc+vite, smoke.ts 엔진, mount-test.ts 빈화면 회귀)를 통과해야 하며, 운영 폴더(포트 4000)는 절대 건드리지 않고 dev(4020)에서만 검증한다.

권장 스택 Recommended Stack

CRDT
Yjs (yjs 13.6.x, 순수 JS·gzip ~18-20KB·WASM 없음). tasks/links/categories/rainySeasons/sheets = Y.Array<Y.Map>, meta/view/paper/branding = Y.Map, palette/mirrorHidden = Y.Array. Task.row·Category.order는 fractional-index 소수 정렬키, parentId는 LWW 값 필드로 move 우회.
전송
온라인 LAN 모드에서만 부착하는 WebSocket provider(HocuspocusProvider, room=projectId). 오프라인 단일 HTML(file://)·서버 다운 시엔 provider 미부착 → y-indexeddb 로컬 영속만으로 완결. 프레즌스는 y-protocols awareness.
서버
Hocuspocus(@hocuspocus/server, MIT). 기존 server/src/index.js의 http.createServer(app) 하나에 부착(추가 포트 없이 4020 유지, 운영 4000 금지). onAuthenticate 훅으로 인증·readOnly 역할. 순수 Node라 Node 24 LTS·Electron 패키징과 호환.
영속·DB
서버: @hocuspocus/extension-database(SQLite/Postgres BLOB) 또는 y-leveldb(MIT, 임베디드, 외부서비스 0). room별 Y.Doc append-log+주기 encodeStateAsUpdate 스냅샷, 임계치 시 재인코딩으로 GC. 클라: y-indexeddb(오프라인 영속, 자동 병합). .json은 스냅샷/백업·레거시 로드용으로 병존.
인증
현재 무인증 0.0.0.0을 하드닝. 최소침습 경로: Caddy forward_auth(또는 nginx auth_request) 리버스프록시로 인증 게이트를 앱 밖에 두고 Express를 127.0.0.1 바인딩(프록시 우회 헤더 스푸핑 차단). CRDT 소켓 인증은 Hocuspocus onAuthenticate 단일 지점. 사내 IdP 없으면 독립 Express auth-server(JWT httpOnly 쿠키). WebSocket 토큰은 쿼리스트링 대신 쿠키/Sec-WebSocket-Protocol 헤더.
프레즌스
y-protocols Awareness — user{name,color}·selection{selectedTaskIds,selectedCategoryIds,selectedLinkId} 필드 브로드캐스트. 기존 zustand selection state 재사용, SVG에 원격 커서·선택 하이라이트 직접 렌더. 재연결 시 clear로 유령 커서 방지(Y.Doc 비저장 휘발 상태라 권위/파생 경계와 무관).
배포
세 배포 형태 공존: (1) 오프라인 단일 HTML(vite-plugin-singlefile, provider 미부착·y-indexeddb만), (2) LAN 서버(Express+Hocuspocus 4020, extension-database 영속), (3) Electron(순수 JS라 무마찰). Node 24.x LTS 강제·Biome·Vite 7 유지. 오프라인/온라인은 provider 부착 여부로만 분기.

근거 — 결정 변수는 성능이 아니라 '배포 제약'이다. HydroNet 최우선 제약(온프레 LAN·오프라인 단일HTML/file://·Electron·무인증→인증 하드닝)에 Yjs만 무마찰로 맞는다: 순수 JS라 단일 HTML 인라인·CSP·WASM 로드 문제 없음, y-indexeddb로 provider 없는 오프라인 영속, MIT 라이선스에 Hocuspocus·Y.UndoManager·awareness가 검증된 기성 조각으로 존재. commit() 단일 쓰기 관문 + CPM 순수 분리라는 코드 구조가 origin 태깅·파생 격리에 교과서적으로 맞아 통합 리스크가 최소다. 문서 규모(수백~수천 tasks)에선 성능이 병목이 아니므로 Loro/Automerge의 성능·이력 우위는 배포 부담을 정당화하지 못한다.

대안(조건부):
  • Loro (MovableList + Movable Tree, MIT, 1.x) — tasks row 재정렬·parentId 세부공정 계층의 동시 이동에서 중복/유실이 mount-test류 회귀로 '실측' 병목으로 드러날 때만 2순위 승격. native movable list/tree가 도메인에 1:1이나 WASM 번들(gzip ~399KB)이 단일 HTML 배포 부담이라 실측 후 결정.
  • Automerge 3.x + automerge-repo — 공정표 '변경 이력'이 제품 기능이 될 때만(베이스라인/개정본 감사추적·시점 열람·되돌리기 로그). 반드시 2.x 아닌 3.x(2025-08, offline 병합 OOM·700MB→1.3MB 수정) 인용. zustand 단일 스토어를 불변 스냅샷 모델로 리라이트하는 비용·WASM 부담이 커 기본 스택으론 비권장.
  • y-sweet (Rust 단일 바이너리, MIT) — Node 프로세스와 분리된 전송 서버를 원하거나 문서(projectId)별 클라이언트 토큰 접근제어를 자연스럽게 붙이고 싶을 때 Hocuspocus 대안. 단 서버 자체 auth 문서가 얕아 앱 서버가 토큰 게이트를 책임지는 구조.
  • 순정 y-websocket-server / PartyKit / Liveblocks / y-redis(yhub) — 권장하지 않음. 순정 y-websocket은 무인증·재시작 시 소실(현 감사 지적 재현), PartyKit은 Cloudflare 런타임 하드종속(폐쇄망 불가), Liveblocks는 프로덕션 자체호스팅 미지원·AGPL, yhub는 Redis 필수·AGPL/상용 이중 라이선스(사내 상용 배포 충돌). 사내 LAN 소수 PC 규모엔 수평 확장 불필요.

아키텍처 Architecture

데이터 흐름은 "Y.Doc = 유일한 진실원본, zustand = 파생 단방향 뷰" 원칙으로 통일한다. 렌더 레이어(App/ChartSvg/Sidebar/Inspector)는 그대로 zustand 셀렉터를 읽으므로 무변경이 목표다.

[1] 클라이언트 Y.Doc ↔ zustand 바인딩 (store.ts 개조)
- Y.Doc 1개를 프로젝트마다 만들고 rootMap=ydoc.getMap('root')에 meta(Y.Map: id/name/kind/facility/startDate/schemaVersion), view(Y.Map), paper(Y.Map), branding(Y.Map), palette(Y.Array), categories/tasks/links/rainySeasons(각각 Y.Array<Y.Map>), sheets(Y.Array<Y.Map> — 비활성 시트까지 전부 상주)를 담는다. 컨테이너는 getMap/getArray가 멱등이므로 부트스트랩 트랜잭션에서 '없으면 1회만' 생성한다(두 클라가 같은 key에 new Y.Array를 set하면 병합이 아니라 덮어쓰기 나므로 절대 재생성 금지).
- 쓰기: 기존 commit(mutate, opts)의 body를 `ydoc.transact(() => applyMutationToYTypes(draftDiff), LOCAL_ORIGIN)`로 감싼다. LOCAL_ORIGIN은 문자열이 아니라 객체 identity(const LOCAL_ORIGIN = {}). commit이 유일한 쓰기 관문이라 origin 태깅 지점이 단 하나 → 교과서적으로 깔끔하다.
- 읽기: ydoc.observeDeep(events => { if (txn.origin === LOCAL_ORIGIN) skipRewrite; else 원격/로컬 공통으로 rootMap.toJSON()을 평면 Project로 뽑아 withSchedule(CPM 로컬 재계산) 후 zustand set })로 단방향 push. observeDeep는 과발화하므로 microtask/requestAnimationFrame 배치로 묶는다. 로컬 origin일 때도 CPM은 재적용해야 하므로 "낙관적 반영 후 CPM만 다시" 경로를 둔다.
- 파생값(es/ef/ls/lf/critical/__mirror/cascade가 민 start)은 어떤 경로로도 Y.Doc에 쓰지 않는다. 단 forceCritical·사용자가 직접 드래그한 start는 권위값이라 트랜잭션에 기록. cascade가 민 start는 SCHEDULE_ORIGIN(비추적) 트랜잭션으로만 반영하거나 아예 로컬 파생으로 유지.

[2] 전송 (온라인 LAN 모드에서만 부착, 옵션화)
- HocuspocusProvider(또는 y-websocket provider) room=projectId로 사내 LAN 서버(ws://호스트:4020/collab)에 붙는다. 오프라인 단일 HTML(file://)·서버 다운 시엔 provider를 아예 부착하지 않는다 → 전송 선택과 오프라인 요건이 분리된다.
- awareness(y-protocols): setLocalStateField('user',{name,color}), 'selection'({selectedTaskIds,selectedCategoryIds,selectedLinkId})을 브로드캐스트. 기존 zustand selection state를 그대로 얹는다. change 이벤트로 원격 커서·선택 하이라이트를 SVG에 직접 렌더. 재연결 시 awareness clear로 유령 커서 방지.

[3] 서버 (server/src/index.js 확장)
- 같은 http.createServer(app) 하나에 Hocuspocus를 부착(추가 포트 없음, 4020 유지, 운영 4000 금지). onAuthenticate 훅에서 토큰/세션 검증(무인증 감사 지적 해소), 실패 시 throw로 연결 차단. 뷰어 역할은 connection.readOnly=true.
- 기존 전체-파일 PUT /api/projects/:id는 CRDT 도입 후 '스냅샷/백업 export' 및 레거시 로드용으로 강등(read-only 또는 삭제). LWW PUT이 CRDT를 덮어쓰지 못하게 하는 것이 5단계 필수.

[4] DB / 영속
- 서버측: @hocuspocus/extension-database(또는 y-leveldb)로 room(projectId)별 Y.Doc 바이너리를 로컬 파일(SQLite/LevelDB)에 append-log+주기 스냅샷으로 영속. 외부 서비스 0개, 인터넷 불필요. 재시작 후에도 문서 복원. 압축은 'mergeUpdates만으로는 삭제분 GC 안 됨' 함정 때문에 임계치 도달 시 Y.Doc 로드→encodeStateAsUpdate 재인코딩 2단계로.
- 클라이언트측: y-indexeddb(PREFERRED_TRIM_SIZE=500 자동 병합)로 provider 없이도 오프라인 편집·영속. 기존 localStorage 자동복원 캐시(AUTOSAVE_KEY)를 이걸로 대체. Y.Doc당 IndexeddbPersistence 인스턴스는 반드시 1개.

[5] 오프라인 / 스냅샷 / 호환
- .json ↔ Y.Doc 왕복 어댑터(api.ts/fileIO.ts, schemaVersion 분기): 로드 시 평면 .json → (서버 권위에서 1회만) CRDT 시드 바이너리 생성·배포(클라별 재import 금지 — clientID 갈려 중복/발산). 저장 시 rootMap.toJSON()으로 순수 Project .json을 그대로 뽑아 기존 파일 포맷 무손실 유지. 베이스라인/개정본 보관은 현 규모에선 '버전마다 전체 스냅샷 복사본 저장'(gc 관리 회피)이 가장 안전.
- 재연결 병합: y-indexeddb가 오프라인 diff를 큐잉했다가 provider 재연결 시 자동 merge(무손실 수렴). 'synced' 이벤트 전 빈 화면 렌더 회귀는 mount-test.ts가 잡는 그 버그이므로 로드 완료까지 대기.

도메인 모델 → CRDT Domain Model

HydroNet 도메인을 Yjs 타입으로 매핑한다. 핵심 원칙: 안정 id(nanoid) 리스트 컬렉션 = Y.Array<Y.Map>, 서로 다른 항목 동시 편집=병합, 같은 필드만 LWW 수렴.

[Project 최상위]
- rootMap = ydoc.getMap('root'). 그 아래:
- meta: Y.Map { id, name, kind, facility, startDate, schemaVersion, createdAt, updatedAt, commissioningEnabled }. 모두 스칼라 LWW 필드.
- view: Y.Map (ViewSettings 필드들 — pxPerDay/rowHeight/scale/showCriticalPath/displayStart/displayEnd/mirrorPlan/showYearLine 등). textStyles는 Y.Map<role, Y.Map>. mirrorHidden은 Y.Array<ID>. paper: Y.Map. branding.logos: Y.Array<Y.Map{src,w,h}>. palette: Y.Array<string>(최대 10).
→ view/paper/branding은 '문서 전체 협업'이 아니라 별도 세밀도로 둘 수 있으나(열린질문 1), 초기엔 같은 Y.Doc에 두고 LWW로 충분.

[Category]
- categories: Y.Array<Y.Map>. 각 Y.Map { id, name, color, collapsed, order, isCommissioning, hidden }.
- 재정렬(order): Y.Array 인덱스 순서에 의존하지 말 것(Yjs native move 부재·delete+insert 시 동시 재정렬이 중복/인터리빙). order를 fractional-index 소수 정렬키(1.0, 1.5, 2.0…)로 두고 '이동=단일 order 필드 LWW 갱신'으로 모델링. reorderCategory/reorderCategories/moveCategory는 두 이웃 사이 중점값 부여로 재작성. collapsed는 로컬 UI 상태라 협업 동기화에서 제외(로컬 뷰) 검토.

[Task]
- tasks: Y.Array<Y.Map>. 각 Y.Map { id, categoryId, name, start, duration, isMilestone, row, color, labelPosition, note, parentId, durationLabel, hidden, forceCritical, progress, isDummy }. 전부 권위 스칼라 필드(LWW).
- row 재정렬 + parentId 재부모화(세부공정)가 CRDT 'move' 직격 지점. 해법 두 갈래:
(a) Yjs 유지(권장): row를 fractional-index 소수키로, parentId를 값 필드 LWW로. moveTaskToRow의 '한 줄 densely renumber'는 절대 인덱스 전면 재작성 금지 → 대상 행 소수키만 계산. 세부공정 계층은 parentId LWW로 수렴(동시 재부모화는 LWW 승자 결정적, 패자 조용히 무효 = 수용기준의 '같은 필드만 결정적 수렴'과 일치). 부모 삭제 시 자식(parentId=부모id) 동반 삭제는 각 클라가 로컬 관찰로 재적용(또는 트랜잭션에 함께 기록).
(b) 이동 정확성이 실측 병목이면 Loro 2순위 승격: MovableList(row)·Movable Tree(parentId 계층·사이클 해소)가 1:1 대응. 단 WASM 번들이 단일 HTML 부담이라 실측 후에만.
- es/ef/ls/lf/totalFloat/critical/__mirror는 Y.Map에 넣지 않음(파생). critical은 forceCritical(권위) 있으면 그 값, 없으면 로컬 CPM.

[Link]
- links: Y.Array<Y.Map>. 각 { id, from, to, type(FS/SS/FF/SF), lag, style, width, showDummy }. 의존성 존재+파라미터가 권위. lag는 사용자 입력 또는 위치역산(relinkIncoming) 결과지만 '드래그 제스처가 만든 lag'는 권위로 기록. 동시성: 서로 다른 링크 편집=병합, 같은 링크 lag 동시 변경=LWW.
- CPM 그래프에 사이클(선후행 순환)이 동시 편집으로 생길 수 있음 → computeSchedule이 사이클을 방어적으로 처리(가지치기/warnings)해야 함. acyclic은 로컬로 검증 불가한 전역 불변식이므로 재계산 함수 레벨 방어 필수.

[RainySeason]
- rainySeasons: Y.Array<Y.Map>{ id, label, startMonth, startDay, endMonth, endDay, efficiency }. 현재 단일 원소(setRainySeason이 [0] 교체)라 사실상 단일 Y.Map로 둬도 무방하나 리스트 유지가 안전.

[Sheet — 멀티시트]
- 현 구조(활성 시트만 최상위 + switchSheet swap)는 CRDT 궁합 나쁨. 전환: 모든 시트를 sheets: Y.Array<Y.Map>에 상주시키고 각 Y.Map { id, role, name, categories/tasks/links/rainySeasons(각각 Y.Array<Y.Map>) }. '활성 시트'는 Y.Doc 상태가 아니라 로컬 뷰 포인터(zustand activeSheetId)로만 관리 → 사용자마다 다른 시트를 봐도 충돌 없음. 최상위 categories/tasks 평면화는 렌더 셀렉터 계층에서 activeSheetId로 파생.
- 대안: 시트별 Y.Subdocument(대형 사업에서 지연로드). 초기엔 단일 Y.Doc 상주로 단순하게.

[CPM 파생 처리]
- withSchedule(computeSchedule) / applyCascade / reschedule / mirror.augmentForMirror는 전부 순수 함수(입력=tasks/links, 출력=새 배열)이며 이미 저장/동기화와 분리돼 있음(코드로 확인). 이 원칙을 유지: CRDT엔 결정적 입력만, 재계산 함수는 순수·결정적, 사이클/전역 불변식은 재계산 단계에서 방어. 수렴은 보장하나 recency는 아니므로 아직 전파 안 된 상대 변경 반영 전 stale CPM이 잠깐 보일 수 있음(최종 일치).

[undo 처리]
- past/future 스냅샷 스택(HISTORY_LIMIT=50) → Y.UndoManager(scope=[tasksY, linksY, categoriesY, rainyY, viewY], trackedOrigins=new Set([LOCAL_ORIGIN])). '내 변경만 undo' 시맨틱(원격 협업자 변경 불건드림). captureTimeout으로 드래그 연속 이동을 1 undo로 병합, 제스처 종료 시 stopCapturing(). CPM 재계산은 SCHEDULE_ORIGIN(비추적)으로 격리해 undo 스택 오염 방지. beginGesture/setTaskStartLive의 history:false 패턴이 captureTimeout·stopCapturing으로 자연 대체됨. 전역→'내 변경만' 시맨틱 변화는 단일사용자 UX 회귀를 mount-test류로 반드시 검증.

[normalize 처리]
- normalize()/migrateSubNameToParentId(레거시 subName→parentId 이관)는 로드 어댑터 계층으로 이동. CRDT 마이그레이션은 가산적(additive) 우선 — 필드 rename 금지(모든 피어 원자적 wipe 불가), 신규 필드는 백필로 흡수. meta.schemaVersion 분기로 멱등 실행(단일 ydoc.transact 안에서).

마이그레이션 · 로드아웃 Migration

  1. 듀얼런(P3~P5): 기존 파일-PUT 파이프라인과 CRDT provider를 한동안 병행. 서버는 CRDT 문서를 진실원본으로 두되, 매 스냅샷마다 rootMap.toJSON()으로 순수 Project .json을 server/data와 ProgramData 자동저장 위치에 함께 써서(백업), 문제가 생기면 즉시 파일 기반으로 롤백 가능하게 한다.
  2. 시드 생성은 서버 권위에서 1회만: 기존 server/data/proj-*.json 각각을 서버가 한 번 로드→normalize/migrateSubNameToParentId→Y.Doc 부트스트랩→encodeStateAsUpdate 바이너리로 영속. 클라이언트는 이 바이너리를 받아 시작하고 절대 각자 .json을 재import하지 않는다(clientID가 갈려 중복/발산).
  3. 데이터 이관 순서: (1) tasks/links/categories/rainySeasons만 먼저 CRDT화(안정 nanoid id라 Y.Array<Y.Map> 1:1), (2) view/paper/branding/palette는 가산적으로 나중에, (3) 멀티시트(sheets)는 P3에서 전 시트 상주 구조로 이관하며 활성 시트를 로컬 뷰로 분리.
  4. 폴백 계층 유지: 클라 api.ts의 serverOk→localStorage 폴백과 y-indexeddb 오프라인 영속을 병존시켜, 서버·provider가 없어도 단일 사용자로 완전 동작(오프라인 단일 HTML은 provider 미부착이 정상 경로).
  5. 스키마 마이그레이션은 가산적으로만: 필드 rename 금지(모든 피어 원자적 wipe 불가), 신규 필드는 로드 어댑터 백필로 흡수, meta.schemaVersion 분기로 멱등 실행. 레거시 subName→parentId 이관은 시드 생성 시 1회 수행 후 CRDT엔 parentId만 상주.
  6. 점진 로드아웃 순서 고정: 무인증→인증(P3 forward-auth/onAuthenticate), 파일저장→DB(P3 extension-database), 단일사용자→협업(P1 로컬→P3 provider). 각 전환은 이전 경로를 강등(read-only)만 하고 즉시 삭제하지 않아 되돌릴 여지를 남긴다(P5에서 LWW PUT 최종 제거).
  7. 검증·배포 원칙: 모든 이관 단계는 dev 폴더(포트 4020)에서만 기동·검증하고 본인 PID만 종료. 운영 폴더(D:\2026\PROGRAM\HydroNet, 포트 4000, main)는 전무님 사용 중이라 절대 수정/재시작/포트점유 금지. 단계 통과 시 build+smoke+mount→README 갱신→commit→git push origin dev + git push github dev(Gitea·GitHub 둘 다 필수).

리스크 & 완화 Risks

파생 스케줄값(es/ef/critical/cascade가 민 start)이 실수로 Y.Doc에 기록되어 사용자끼리 서로 덮어쓰며 진동한다
↳ 권위=사용자 입력값만 트랜잭션에 기록. CPM은 SCHEDULE_ORIGIN(비추적) 또는 로컬 파생으로만 재적용. forceCritical·사용자 드래그 start만 권위. P0 경계 문서를 코드 리뷰 게이트로 강제하고 '파생값이 CRDT에 없음'을 P3 수용기준에 명시.
Task.row 재정렬·parentId 세부공정 재부모화를 Y.Array 인덱스/delete+insert로 처리하면 동시 이동 시 공정 중복·인터리빙·편집 유실
↳ row/order를 fractional-index 소수 정렬키로, parentId를 LWW 값 필드로 모델링('이동=단일 필드 갱신'). moveTaskToRow의 densely renumber를 이웃 중점값 계산으로 재작성. 실측 병목이면 Loro MovableList/Movable Tree로 2순위 승격 검토.
zustand↔Yjs 무한루프: 로컬변경→Yjs쓰기→observe→store 되쓰기→다시 Yjs쓰기
↳ origin 태깅(LOCAL_ORIGIN=객체 identity, 문자열 금지). observeDeep에서 origin===LOCAL_ORIGIN이면 되쓰기 skip. Y.Doc을 진실원본, zustand는 단방향 파생 뷰로.
중첩 컨테이너 덮어쓰기: 두 클라가 같은 map key에 각각 new Y.Array를 set하면 병합 아니라 한쪽 소멸
↳ 컨테이너는 부트스트랩에서 정확히 1회만 생성(getArray/getMap 멱등 + 존재체크 guard). 모든 클라는 get()으로 기존 배열을 가져와 push.
멀티시트의 '활성 시트만 최상위 + switchSheet swap' 구조가 CRDT와 궁합 나쁨(swap이 대규모 덮어쓰기)
↳ 전 시트를 sheets: Y.Array<Y.Map> 상주로 전환, '활성 시트'는 Y.Doc 상태 아닌 로컬 뷰 포인터(zustand)로만. 사용자마다 다른 시트를 봐도 충돌 없음.
무인증 0.0.0.0 Express — 프록시 우회 헤더 스푸핑·CRDT 소켓 무인증 노출
↳ Express를 127.0.0.1 바인딩하고 프록시만 0.0.0.0 노출(forward-auth). CRDT는 Hocuspocus onAuthenticate 단일 관문. WebSocket 토큰은 쿼리스트링 대신 쿠키/Sec-WebSocket-Protocol.
단일 HTML(file://)/Electron에서 WASM·번들 부담
↳ 순수 JS Yjs 채택(WASM 없음, gzip ~18KB 인라인 가능). 오프라인은 provider 미부착+y-indexeddb만. Automerge/Loro의 WASM는 단일 HTML엔 부적합이라 배제. build:single·check-single로 회귀.
서버 영속 용량 팽창(mergeUpdates는 삭제분 GC 안 함) 및 버전 히스토리 gc=false로 무한 증가
↳ 압축 2단계: append-log + 임계치 시 Y.Doc 로드→encodeStateAsUpdate 재인코딩(진짜 GC). 마일스톤 규모는 gc=true 기본으로 안정. 베이스라인은 '버전마다 전체 스냅샷 복사본' 저장으로 gc 관리 회피.
undo 시맨틱 변화(전역→내 변경만)로 단일 사용자 UX 회귀
↳ trackedOrigins={LOCAL_ORIGIN}로 '내 변경만' 격리하되 단일 사용자에선 기존과 무차별함을 mount-test류 회귀로 검증. captureTimeout·stopCapturing으로 제스처 병합 경계 재현.
동시 편집으로 링크 그래프에 사이클 발생 → CPM이 비결정적/무한루프. acyclic은 로컬 검증 불가한 전역 불변식
↳ computeSchedule이 사이클을 방어적으로 처리(가지치기·warnings). 재계산 함수 레벨에서 순수·결정적 보장. 수렴은 되나 recency 아님(stale CPM 잠깐 표시, 최종 일치)을 UX로 수용.
운영 폴더(포트 4000, main)를 실수로 건드려 전무님 서버 중단
↳ 모든 개발·검증은 dev 폴더·포트 4020(또는 4000 외)에서만. 본인이 띄운 PID만 종료. 절대 규칙으로 CLAUDE.md에 명시됨.
에어갭 사내망에서 npm 레지스트리 접근 불가로 의존성 반입 실패
↳ node_modules 벤더링 또는 Verdaccio 미러로 의존성 사전 반입. LAN 내부는 ws:// 또는 자체서명 인증서.

착수 전 확인 Open Decisions

  • 협업 단위: 문서 전체를 하나의 Y.Doc으로 vs tasks/links/categories만 CRDT로 하고 view/paper/branding은 별도 세밀도(또는 로컬)로? (초기 권고: 단일 Y.Doc, view/paper는 LWW로 함께 — 단 collapsed 등 순수 UI 상태는 로컬 뷰로 뺄지 결정 필요)
  • 멀티시트 상주 방식: 전 시트를 단일 Y.Doc에 상주 vs 시트별 Y.Subdocument로 지연로드? (대형 사업 규모·시트 수에 따라. 초기 권고: 단일 Y.Doc 상주)
  • 서버 영속 백엔드: Hocuspocus extension-database(SQLite/Postgres, SQL 조회 가능) vs y-leveldb(임베디드·설치 0)? (SQL로 프로젝트 목록·감사 로그 조회 필요성이 실제 있는지)
  • 인증 방식: 리버스프록시 forward-auth(사내 IdP/SSO 있을 때) vs 독립 Express auth-server(JWT 쿠키) vs 앱 내장 세션? 사내에 Keycloak/Authelia 등 IdP가 있는지 확인 필요
  • 역할 모델: '전무님=쓰기, 현장 PC=읽기' 같은 문서별 RBAC/readOnly가 실제 필요한지, 아니면 LAN 내 전원 편집 가능으로 충분한지
  • 변경 이력이 '제품 기능'인지: 공정표 베이스라인/개정본 감사추적·시점 열람이 요구사항이면 Automerge 3.x 재검토 트리거. 아니면 Yjs '버전 스냅샷 복사본'으로 충분
  • Loro 승격 조건 수치화: '동시 이동 시나리오에서 중복/유실이 mount-test 회귀로 재현되는가'를 실제 벤치로 확인해 Yjs fractional-index로 충분한지 판정
  • 오프라인 클라의 readOnly 처리: readOnly 사용자의 로컬 y-indexeddb 미수락 변경을 서버본으로 교체하는 정책(오프라인-퍼스트와 충돌 지점)을 어떻게 UX 설계할지
  • collapsed·activeSheet·selection 등 '로컬 뷰 상태'를 어디까지 동기화에서 제외할지 확정(사용자마다 다른 뷰 허용 범위)
  • 에어갭 배포 확정: 사내망이 npm 레지스트리·외부에 닿는지, node_modules 벤더링/Verdaccio 미러가 필요한지
