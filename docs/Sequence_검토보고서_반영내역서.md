## 2. 과제별 반영 내역

### P0 — 확대 적용 전 해결

**F01 저장·동기화·파일 백업 구분** — 충족
`state/persistence.ts` 신설. 표시 상태를 `서버 동기화 완료 / 서버 확정 대기 / 전송 대기 / 연결 끊김 /
로컬만 저장` 과 `파일 백업` 으로 분리했습니다. **‘서버 동기화 완료’ 는 연결 상태가 아니라 실제
영속 확인에 근거합니다** — 서버가 `storage.store()` 성공 **후에** 상태벡터·삭제 총량을 실은 확정
메시지를 보내고, 클라이언트는 그 값이 자기 편집을 담고 있을 때만 완료로 표시합니다. 파일 백업
시각도 `save()` 의 실제 성공 여부로만 기록합니다(대화상자를 취소하면 기록하지 않음).

**F02 기본 검증 17건 실패** — 충족
14건은 **실제 데이터 결함**이었습니다(토목 프리셋 12종에서 착공이 첫 공정보다 늦거나 준공이 작업
종료보다 빨랐음). 마일스톤을 뒤로 미루는 방향으로 통일해 교정했고, 어떤 공정의 공기(`months`)도
바꾸지 않았습니다(표준공기 색인이 흔들리기 때문). 3건은 **낡은 기대값**이었습니다 — 커밋
`55236f3` 이 ‘한 줄에 하나씩’ 배치로 바꾼 뒤 갱신되지 않은 단정문이라, 현재 설계를 검증하도록
고쳐 썼습니다(허용 오차를 좁히고 조건을 추가해 **더 엄격**해졌습니다). 판정에 있던 ±1일 여유도
제거했고, 그러자 숨어 있던 위반 1건(사방댐)이 추가로 드러나 함께 고쳤습니다.

**F03 병렬 공정·산정 가정** — 충족
`작업량 합계`와 `경과 공기`를 분리했습니다. 경과 공기는 선후행 네트워크를 실제로 재계산해
구합니다(병렬 10일 공정 2개 → 합계와 경과가 구분되어 산출). 준비·정리·공휴일·기상·허용 편차를
프로젝트 입력값으로 만들었고(CRDT 필드 단위 병합), 입력하지 않으면 **‘가정 기반 참고값’** 으로
표시합니다. ±15%가 제품 기본값이지 법정 수치가 아니라는 점, 준비기간 30일에 가이드라인 근거가
없다는 점을 화면과 `.md` 양쪽에 명시했습니다.

**F04 물량 단위 불일치** — 충족
`engine/units.ts` 신설. 엔진 경계에서 단위를 정규화·차원 검사합니다. `m³/㎥/m3` 동의어는 허용하고,
`ton` ↔ `㎥` 처럼 근거 없는 환산은 차단해 **‘판정불가’** 를 반환합니다(그럴듯한 숫자를 만들지
않습니다). Inspector · BoQ 취입 · AI 검토요청서 **모든 경로**에 같은 검증이 걸립니다.

**F05 서버 장애 ≠ 로컬 사용 의도** — 충족
배포 형태를 빌드 시점에 명시하고, 서버 대상 배포에서는 `/health` 실패 시 재시도 후 안내 화면을
띄웁니다. 오프라인 단독 실행본은 첫 화면부터 로컬 전용임을 표시합니다.

### P1 — 시범 운영과 함께 개선

**F06 간편 모드·첫 도면 안내** — 충족
첫 실행 시 목적(작성/수정/조회)을 묻고 실제로 화면·모드를 바꿉니다. 5단계 안내의 각 단계는
**‘다음’ 버튼이 아니라 실제 상태 변화로만** 체크됩니다(PDF 단계는 실제 다운로드 앵커가 DOM에
삽입되어야 켜집니다).

**F07 초대·배정·입장** — 축소 반영
접근 요청 흐름을 붙였습니다(담당 PM 안내 → 요청 → 승인/거절, 요청자·승인자·기한·거절 사유 기록).
**요청이 접근을 주지 않는다**는 점, 본인 요청을 본인이 승인할 수 없다는 점을 검사로 못 박았습니다.
› 제외: **타 본부 협업 예외는 구현하지 않았습니다.** 요청 가능 범위를 기존 본부 경계 안으로 묶어
권한 정책을 1mm도 넓히지 않았습니다 — 업무 정책 결정이 먼저입니다.

**F08 프로젝트 목록 = 개인 업무 홈** — 축소 반영
내 프로젝트·즐겨찾기·최근·전체 탭 + 이름 검색. 검색·필터는 서버가 이미 권한으로 걸러 준 목록에서
고르기만 하므로 권한 범위가 목록과 항상 같습니다(검사로 확인).
› 제외: 즐겨찾기·최근은 **사용자별 localStorage** 입니다. PC를 바꾸면 초기화됩니다.

**F09 막대 이동과 지연값** — 충족
`위치 자유 편집`(기존 동작)과 `선후행 제약 유지`를 분리했습니다. 제약 유지 모드에서는 lag가
임의로 다시 계산되지 않습니다(FS/SS/FF/SF·다중 선행 전부 검사). 이동 전 영향(시작일·lag·후행·준공)
요약과 되돌리기를 제공하며, 되돌리기 버튼은 그 편집이 실행취소 스택의 맨 위일 때만 나타납니다.

**F10 계산 경고 → 문제 목록** — 충족
순환을 **전부** 찾아 목록으로 보여주고 해당 공정·연결로 이동합니다. 미해결이면 산정 결과를
`잠정`으로 표시하고, 출력 사전 점검과 AI 검토요청서에도 미해결 여부를 싣습니다. 조용히 버려지던
자기참조 연결도 문제로 드러냅니다.

**F11 키보드·모달·도움말** — 충족
`state/keymap.ts` 를 단일 정의로 두고 도움말을 여기서 생성합니다. 범위(전역/캔버스/편집기)를
바인딩마다 판정하므로 입력 중 Ctrl+Z가 도면을 바꾸지 않고, 대화상자 위에서도 Ctrl+S는 동작합니다.
공통 모달에 초기 포커스·Tab 순환·복귀·`aria-labelledby` 를 넣었고, 닫히는 중(170ms)에는 편집기
단축키가 다시 살아나지 않습니다.

**F12 일정표 취입** — 축소 반영
`state/scheduleImport.ts` · `export/scheduleTemplate.ts` 신설. 양식 내려받기 → 열 매핑 → 행별 계획
미리보기(신규/갱신/오류) → 선택 반영, 100행 왕복에서 ID·날짜·기간·연결 의미가 보존되고 전체
취입이 실행취소 1회로 되돌아갑니다. 공종을 찾지 못한 행은 **오류로 표시**하며 첫 공종으로 조용히
밀어 넣지 않습니다.
› 제외: **사내 표준 1종**만 지원합니다. MS Project XML · P6 XER 는 하지 않았습니다(보고서가
‘모든 외부 일정 포맷 지원’을 현재 우선순위에서 제외했습니다).

**F13 변경 이력·검토·확정본** — 축소 반영
공정별 변경 사유·작성자·시각을 기록하고 `검토요청 → 확정` 상태를 붙였습니다. 확정본을 버전으로
보존하고 현재 계획과 날짜 차이를 비교합니다. 감사기록은 실행취소 대상이 아니며, **복구·파일
열기로도 지워지지 않습니다**(합집합 병합).
› 제외: **‘확정본 재출력’ 중 도면 재출력은 미구현**입니다. 확정본의 공정 목록과 차이표는 인쇄할 수
있지만, 승인 당시의 A1 도면을 다시 렌더링하는 경로는 없습니다. 화면에도 그렇게 적었습니다.

**F14 출력 범위** — 충족
`전체 도면 / 현재 표시 범위`를 명시적으로 선택하며 실제로 출력물이 달라집니다. 사전 점검
(`export/preflight.ts`)이 최소 글자 크기·잘림·숨김 항목·기간 절단·분할 장수를 알려주고, 실패 시
재시도·낮은 DPI·진단 정보 복사로 연결합니다.

**F15 저장 → 복구 가능한 운영 체계** — 축소 반영
서버 보관을 **프로젝트 이름 키에서 ID+버전 키로** 바꿨습니다(동일명 프로젝트 충돌 해소). 버전
목록·미리보기·복구 UI를 붙였고 보관 상한과 프루닝이 있습니다. 본문을 그대로 싣던
`POST /api/autosave` 는 폐지했습니다(위조 이력 적재 경로였음). 버전 쓰기 경로는 **편집 권한 + 속도
제한 + 최소 간격**을 요구하고, 파괴적 삭제는 개발자만 가능합니다.
› 제외: RPO/RTO 목표치는 **운영 담당자와 합의할 사항**이라 수치를 정하지 않았습니다. PostgreSQL
경로의 SQL은 이 환경에 DB가 없어 실행 검증하지 못했습니다.

**F18 교육·지원·효과 측정** — 축소 반영
`docs/Sequence_15분_교육안내.md` · `docs/Sequence_본부별_업무예제.md`(11개 본부 각 1건) ·
`docs/Sequence_지원체계_및_도입효과_측정.md` 신설. 앱에 **🛟 문의 → 진단 정보 복사** 를 붙였습니다.
› 제외: 문서의 사람·일정·목표치는 `⬜` 로 비워 두었습니다 — **지어내지 않았습니다.** 실제 사용률·
만족도 측정은 코드가 할 수 있는 일이 아닙니다.

### P2 — 효과 확인 후 확장

**F16 계획 이후의 재접속 이유** — 충족
담당자·실적 착수/완료일을 넣고 주간 공정회의 자료를 자동 집계합니다(지난주 착수·완료·지연,
다음주 착수 예정, 누계 편차·SPI). 누계 지연 경보를 추가하고, `%p` 와 SPI 산식을 화면에 적었습니다.

**F17 작은 화면** — 축소 반영
좁은 화면에서 좌우 패널을 서랍으로 접어 차트 폭을 확보합니다(CSS 숨김이 아니라 렌더 트리에서
제외). `smoke:perf` · `bundle:report` 로 실측 하네스를 만들고 기준값을 기록했습니다.
› 제외: **번들 분할·성능 최적화는 하지 않았습니다.** 보고서가 ‘측정 먼저’라고 했고, 실측 결과
1000공정 p95 4.1ms 로 예산(120ms) 안에 있어 착수 근거가 없습니다. 모바일은 조회·검토·진척 입력
범위로 한정했습니다.

## 3. 반영하지 않은 것 — 보관 검토서의 장기 과제

`docs/` 의 다른 검토서(도메인 연동·세계우위 전략·설계감리 실무적합성)에서 나온 항목 중 아래는
**의도적으로 제외**했습니다. 직원활용성 검토보고서가 “지금 확대하지 않을 범위”로 못 박은 것과
겹치거나, 저장소에 없는 외부 데이터가 필요합니다.

| 항목 | 제외 사유 |
| --- | --- |
| 조달청 세부공종분류코드 데이터셋 취입 | 권위 있는 원본이 저장소에 없음. **코드를 지어내지 않았습니다.** |
| 표준품셈 원문(HWP) 반자동 추출 | 원본 문서와 추출 파이프라인 부재 |
| MS Project XML · P6 XER 입출력 | 보고서가 ‘모든 외부 포맷 지원’을 현재 우선순위에서 제외 |
| 몬테카를로 P50/P80 · 3점 추정 | 결정론 산정의 전제(단위·병렬)가 먼저 정리되어야 함 |
| 자원(인력·장비) 평준화 | 자원 모듈이 아직 공정과 연결되지 않은 자유 텍스트 기록표 |
| BIM/IFC 4D · CV 현장 진척 인식 | 착수 근거 없음 |
| 감리 법정 별지서식 자동 채움 | 서식 원본·검증 절차 확보 후 |
| MCP stdio 어댑터 · 로컬 소형 LLM | 현재 뉴로심볼릭 경계(엔진이 산정, LLM은 서술)로 충분 |

## 4. 남은 위험

- **PostgreSQL 경로 미검증** — 인증·접근 요청의 pg 어댑터 SQL은 실 DB 왕복을 돌리지 못했습니다.
  메모리 어댑터와 같은 예외 계약을 맞춰 두었지만, 운영 배포 전 실 DB에서 한 번 확인해야 합니다.
- **래스터·벡터 출력물 자동 검사 부재** — PNG/JPG/PDF/SVG 산출물 자체를 검사하는 스모크가 없습니다.
  사전 점검과 DXF 범위까지만 자동화되어 있습니다.
- **`civilFacilities.ts` 는 생성물** — 이번 프리셋 교정은 수기입니다. 워크플로로 재생성하면 조용히
  되돌아갑니다(파일 상단에 경고 주석을 남겼습니다).
- **보고서 본문의 실행 결과표는 검토 시점 값** — 현재 값은 `docs/review-evidence/` 입니다. 보고서는
  검토 당시를 서술한 문서이므로 수정하지 않았습니다.
