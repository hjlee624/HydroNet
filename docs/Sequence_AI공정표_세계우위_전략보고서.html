토목·물 인프라 공정표 소프트웨어,
AI 시대에 세계 우위를 선점하는 길

현행 제품 Sequence(CPM 기반 공정표·마일스톤 협업 도구)의 코드 베이스라인을 진단하고, 글로벌 스케줄링 강자(Primavera P6·MS Project·Asta)와 AI 신흥주자(ALICE·nPlan·Buildots·Doxel)의 검증된 경쟁 지형을 근거로, 무엇을 더해야 세계 우위를 확보하는가를 실무형(6–12개월)과 프런티어(문샷)로 나누어 제시한다.

00

핵심 요약 — 세 가지 전략 결론

결론부터. 세계 시장의 "AI 공정표" 경쟁은 이미 세 축으로 굳어졌고, Sequence는 아직 결정론적 CPM 단계에 있다. 그러나 승부처는 순수 LLM이 아니라 뉴로-심볼릭(LLM + 우리 CPM 엔진)이며, 이 지점에서 우리는 오히려 유리한 출발선에 서 있다. 진짜 해자는 한국 수자원·댐·하천·상하수도 실적 데이터다.

1

시장은 이미 3축으로 굳어졌다

① 생성형·최적화 스케줄링(ALICE, 수백만 시나리오로 공기 최대 20%↓)[1], ② 과거 빅데이터 기반 ML 지연예측(nPlan, 75만+ 공정 파일·GNN)[3], ③ 상용 CPM의 내장 몬테카를로+AI 리스크(Oracle Primavera Cloud)[7].

우리는 아직 결정론적 CPM 단계
2

승부는 "뉴로-심볼릭"에서 난다

학계 결론은 명확하다 — LLM 단독 계획은 실패(PlanBench <12%)하고, LLM 프런트엔드를 고전 CPM/심볼릭 엔진과 결합해야 진짜 성능이 나온다.[11][12] 우리는 이미 견고한 CPM 엔진(scheduling.ts)을 보유 — 절반은 이미 지었다.

엔진은 있다 · LLM 프런트엔드만 얹으면 된다
3

세계 우위의 해자 = 국내 데이터

범용 글로벌 툴이 못 가진 것: 한국 표준품셈·수자원공사·댐·하천·상하수도 실적. S-Construction 2030으로 표준품셈·건설기준 약 1,079개가 기계판독화되는 중[21] — 도메인 특화 학습의 원료가 제도적으로 열린다.

글로벌 기능 × 국내 데이터 튜닝 = 대체 불가

🧭 한 문장 전략

"검증된 글로벌 AI 스케줄링 기능(생성형 최적화·확률 예측·BIM 연동)을, 우리 CPM 엔진 위에 뉴로-심볼릭으로 얹고, 한국 수자원·표준품셈 데이터로 튜닝한다." — 이것이 카피 불가능한 세계 우위의 공식이다.

01

현황 진단 — 지금 우리가 선 자리

Sequence의 코드베이스를 실측했다. 결론: 스케줄링 "코어"는 세계 수준에 손색없이 견고하나, "지능(AI)"과 "상호운용성"은 전면 공백이다. 이 공백이 그대로 로드맵의 뼈대가 된다.

✅ 이미 갖춘 것 — 강점 (출발선)

  • 진짜 CPM 엔진 — 전진/후진 패스, ES·EF·LS·LF, 총여유(float), 주공정선 자동 판정 engine/scheduling.ts
  • 4종 의존관계 + lag — FS/SS/FF/SF, 연쇄수정(cascade)·자동 리스케줄·순환 감지
  • 시설물 유형별 표준 공정 템플릿 — 댐·수력 9종 + 토목 다분야 ~33종(도로·교량·터널·하천·상하수도·항만·철도) data/civilFacilities.ts
  • 실시간 협업(CRDT) — Yjs + Hocuspocus, 본부 RBAC, 네이버웍스 알림
  • 기후 인식의 씨앗 — 우기(강우) 효율 밴드 RainySeason.efficiency, 진척률 Task.progress

❌ 아직 없는 것 — AI·지능 공백 (기회)

  • AI/ML 전무 — 자연어→공정표, 공기 예측, 지연 리스크 예측, 자동 최적화 없음
  • 자원·인력·장비·원가·물량(품셈) 런타임 모델 없음 → 자원 평준화 불가 (Task에 자원 필드 부재)
  • 확률/리스크 시뮬레이션 없음 — 몬테카를로·P50/P80 완공확률 곡선 없음
  • 글로벌 상호운용성 부재 — P6 XER / MS Project XML / IFC import·export 없음 (독자 JSON + SVG/PNG/PDF/DXF만)
  • BIM/4D·현장 진척 자동 인식 없음 — 드론/영상/센서 연동 없음

* 흥미로운 자산: 현재 시설물 템플릿은 이미 딥리서치 워크플로로 저작된다(scripts/gen-civil.mjs). 즉 AI를 "저작 시점"에 쓰는 문화·파이프라인은 이미 사내에 존재한다 — 이를 "런타임 제품 기능"으로 승격하는 것이 이 로드맵의 골자다.

02

세계 경쟁 지형 — 벤치마크

"AI 공정표"는 마케팅 구호가 아니라 이미 매출과 실증이 붙은 세 갈래다. 각 축의 대표 주자와 검증된 사실만 정리한다 (벤더 자체 발표 수치는 반드시 그 출처에 귀속해 읽는다 → §6).

03

무엇을 더할 것인가 — 기술 로드맵

7개 기능 영역. 각각 실무형 6–12개월 과 프런티어 · 문샷 으로 나누고, 우선순위(P0 필수기반 · P1 차별화 · P2 문샷)와 우리 코드에 어떻게 붙는지까지 명시한다.

F1 자연어 → 공정표 초안 생성 (뉴로-심볼릭) P0

"40m 콘크리트 중력댐, 착공 2026-03, 우기 6–9월, 공기 40개월" 같은 자연어 한 문장에서 시설물 유형·공종·개략 물량을 파싱해 초안 공정표를 자동 생성. 핵심 설계 원칙: LLM은 절대 날짜·CPM을 직접 계산하지 않는다. LLM은 구조(공종/공정/의존성/개략 기간)만 뽑고, 실제 스케줄 계산은 우리 CPM 엔진이 한다.

🟢 실무형 (6–12개월)
  • LLM이 자연어 → 구조화 출력(공종·공정·FS/SS 의존성·개략 duration)
  • 기존 CIVIL_FACILITIES 템플릿을 RAG 앵커로 사용 → 환각 억제
  • 대화형 편집("여수로를 2개월 당겨줘") → 엔진이 재계산
🟡 프런티어 (문샷)
  • 완전 자동 WBS 생성(설계 문서·시방서 → 공정 네트워크)
  • LLM-Modulo식 강결합(엔진이 위반을 LLM에 되먹임하며 반복 정련)
  • 양방향: 도면/BOQ + 자연어 → 통합 초안
구현 접근: LLM 출력 스키마 = 우리 Task[] / Link[] 형태로 직결. 생성 후 applyCascade()→computeSchedule()가 ES/EF/주공정을 계산하므로 LLM의 산술 오류가 스케줄에 침투하지 못한다. 이미 있는 템플릿→cascade 파이프라인에 얹기 가장 쉬운 첫 기능.

근거: 뉴로-심볼릭 원칙 [11][12] · 건설 도메인 실증 CONSTRUCTA [13] · 멀티에이전트 WBS 생성 [14]

F2 몬테카를로 리스크 시뮬레이션 (확률형 공정표) P0

결정론적 "한 줄 공기"를 넘어, 각 공정에 불확실성 분포(낙관·최빈·비관)를 주고 몬테카를로로 굴려 완공일 P50/P80 확률곡선과 주공정 확률(criticality index)을 산출. Oracle이 이미 표준화한, 세계 무대의 최소 자격 요건.

🟢 실무형 (6–12개월)
  • Task에 3점 추정(min/likely/max) 필드 추가
  • computeSchedule() 위에 MC 반복(수천 회) 레이어 → 완공확률 S-곡선
  • 공정별 criticality %, 지연 기여도 토네이도 차트
🟡 프런티어 (문샷)
  • 베이지안-몬테카를로 연속 갱신: 현장 진척이 들어올 때마다 분포 자동 업데이트
  • 기후·규제 리스크를 분포 파라미터에 결합(→ F7)
구현 접근: 엔진이 순수 함수(새 데이터 반환)라 MC 반복에 이상적 — 워커 스레드에서 computeSchedule()를 N회 호출. 우기 밴드(RainySeason.efficiency)를 확률 변수로 승격하면 강우 리스크가 정량적으로 완공확률에 반영된다(국내 특화 연결점).

근거: 상용 내장 몬테카를로 표준 [7][8] · 베이지안-MC 연속 갱신 중간 확신[17][18]

F3 과거 실적 기반 공기·지연 리스크 예측 (nPlan식) P1

우리가 협업 서버에 쌓는 프로젝트(계획 vs 실적)를 학습해, 새 공정표의 활동별 지연확률·현실적 공기를 예측. nPlan의 핵심은 데이터 규모지만, 우리는 국내 수자원·댐 실적이라는 좁고 깊은 데이터로 시작한다.

🟢 실무형 (6–12개월)
  • as-planned vs as-built 수집 파이프라인(진척 데이터 축적)
  • 공종·시설물 유형별 공기 편차 통계 → "이 유형 평균 지연" 벤치마크 경보
  • SBERT 의미유사도로 유사 과거공정 공기 추정
🟡 프런티어 (문샷)
  • GNN(스케줄 DAG) 학습형 활동 성과 예측
  • "인간 추정 대체" 수준의 자동 리스크 스코어링
구현 접근: 데이터 자산이 선결. 협업 서버(pg/Yjs 스냅샷)에 계획·실적 버전을 남기는 것부터 시작 → 초기엔 통계·유사도(경량)로, 데이터가 쌓이면 GNN으로 승격. 지금 데이터 로깅을 시작하지 않으면 이 해자는 못 만든다.

근거: nPlan GNN·75만 공정 학습 [3][5] · SBERT 공기추정 [15]

F4 자원·원가(품셈) 모델 + 자동 자원 평준화·최적화 P0 데이터모델 P2 최적화

현재 가장 큰 단일 공백. Task에 자원/장비/인력/원가/물량이 없어 자원 평준화·비용 곡선·생성형 최적화가 원천 불가. 표준품셈 기계판독화(S-Construction 2030)를 원료로 공정별 물량 → 인력·장비·원가 자동 산출 체계를 세우고, 그 위에 ALICE식 최적화를 얹는다.

🟢 실무형 (6–12개월)
  • 자원·원가 필드 도입 → 자원 히스토그램·S-커브·인력 평준화(고전 알고리즘)
  • 표준품셈 매핑 테이블로 공종별 표준 원단위 자동 배정
🟡 프런티어 (문샷)
  • 생성형 최적화: 자원·공간·시퀀스를 변수로 수천~수백만 시나리오 탐색(ALICE급)
  • DRL(강화학습) 자동 리스케줄 — 제약 위반 없는 재배치
구현 접근: types/model.ts의 Task 확장이 출발점(자원 배열·원가·물량). 스키마 버전업 필요. reschedule()가 이미 "최조기 배치" 최적화를 하므로, 자원 제약을 추가한 RCPSP(자원제약 스케줄링)로 확장하는 자연스러운 경로.

근거: 생성형 최적화 스케줄링 [1][2] · DRL 자동 스케줄링 [20] · 표준품셈 기계판독화 [21]

F5 4D BIM/IFC 연동 + 글로벌 상호운용성 (P6·MSP·IFC I/O) P0

세계 무대·대형 발주 진입의 통행증. 현재 독자 JSON + DXF만으로는 P6/MSP 생태계와 대화 불가. 동시에 BIM 모델 → 활동·공기 자동 생성은 국내 BIM 의무화 물결과 정확히 맞물린다.

🟢 실무형 (6–12개월)
  • P6 XER / MS Project XML import·export
  • IFC 4D 매핑(활동↔부재) 기초, BOQ→활동 리스트 자동 생성
🟡 프런티어 (문샷)
  • BIM→공기·시퀀스 완전 자동화(SBERT 공기추정 파이프라인)
  • 4D 시뮬레이션 뷰(모델 위 공정 재생)
구현 접근: state/fileIO.ts·export/exporter.ts에 포맷 어댑터 추가. XER/MSPDI는 잘 문서화된 스키마 → 우리 Project 모델과 매핑만 정의하면 됨. 상호운용성은 기술 난도는 낮고 시장 진입 효과는 큰 고ROI 항목.

근거: BIM-NLP 자동 스케줄(Revit→BOQ→활동·공기) [15][16] · S-Construction 2030 BIM 의무화 [21]

F6 현장 진척 자동 인식(드론/영상/센서) → 디지털 트윈 P2

Doxel·Buildots식 컴퓨터 비전으로 as-built를 자동 수집해 Task.progress를 자동 갱신하고, 그 신호가 F2 베이지안 갱신·F3 예측을 트리거하는 살아있는 디지털 트윈 루프.

🟢 실무형 (부분)
  • 모바일 진척 입력·사진 첨부 → 진척 로그(비전 없이도 데이터 축적 시작)
  • 드론 정사영상 타임랩스 오버레이(수동 판독 보조)
🟡 프런티어 (문샷)
  • CV 자동 진척 인식 → 계획 대비 편차 자동 경보
  • 물 인프라(댐·제방·관로) 특화 진척 인식 모델
구현 접근: Task.progress 필드가 이미 존재 → CV 파이프라인의 출력을 꽂을 자리는 준비됨. 단, 물 인프라 현장에서의 CV 진척 인식은 검증 공백(§7 미해결 질문)이라 문샷으로 신중 배치.

근거: Doxel [24] · Buildots [25] · WAMIS 수자원 디지털 트윈 [22]

F7 규제·기후 리스크 정량화 (국내 특화 해자) P1

범용 글로벌 툴이 흉내 못 내는 지점. 우기·홍수·가뭄·환경영향평가·방재 기준·수문 조건을 스케줄 리스크로 정량화한다. 우기 밴드는 이미 있다 — 이를 확률·수문 데이터와 결합해 "기후 인식 공정표"로 승격한다.

🟢 실무형 (6–12개월)
  • 우기 효율 → 확률 리스크로 승격(F2 결합), 홍수기 제약 자동 반영
  • 환경영향평가·인허가 리드타임을 공정 제약으로 템플릿화
🟡 프런티어 (문샷)
  • WAMIS 실시간 수문·강우 데이터 연동 → 동적 공정 리스크
  • 기후 시나리오(극한강우)별 공기 스트레스 테스트
구현 접근: RainySeason.efficiency를 확정값이 아닌 확률 분포로 확장하고, WAMIS API[22]를 데이터 소스로 연결. 이 기능은 기술 난도보다 도메인 데이터 확보가 관건 — K-water·환경부 데이터 접근이 핵심 자산.

근거: WAMIS 디지털 트윈 [22] · 국내 수자원 스케줄링 연구 [23] 전략적 추론

04

우선순위 로드맵 — 자격 → 차별화 → 해자

"한 번에 다"가 아니라 순서가 전략이다. 먼저 세계 무대에 설 자격(상호운용성·확률·자원)을 갖추고, 그다음 AI 차별화(뉴로-심볼릭·예측)로 앞서가며, 마지막에 대체 불가 해자(국내 데이터·생성형 최적화·디지털 트윈)를 판다.

0–6개월
Phase 1
세계 무대 자격
"P6와 대화되고, 확률로 말하는" 도구
  • F5 P6 XER / MSP XML I/O P0
  • F2 몬테카를로 리스크(P50/P80) P0
  • F4 자원·원가 데이터모델 착수 P0
  • F3 계획·실적 데이터 로깅 시작
6–12개월
Phase 2
AI 차별화 1차
"말로 짜고, 리스크를 예견하는" 도구
  • F1 자연어→공정표(뉴로-심볼릭) P1
  • F3 유사공정 공기예측·지연경보 P1
  • F7 기후·규제 리스크 정량화 P1
  • F4 자원 평준화·S커브
12–24개월
Phase 3
대체 불가 해자
"국내 데이터로 스스로 최적화하는" 도구
  • F4 생성형 최적화·DRL 리스케줄 P2
  • F6 CV 현장 진척 → 디지털 트윈 P2
  • F3 GNN 학습형 예측(국내 실적)
  • F1 BIM+문서 완전 자동 WBS

🛡️ 왜 이 순서인가 — 해자의 논리

Phase 1·2의 기능(확률·자연어·예측)은 경쟁사도 카피할 수 있다. 그러나 Phase 3의 "국내 수자원·표준품셈 실적으로 학습된 최적화·예측 모델"은 데이터 없이는 복제 불가능하다. 그래서 F3의 데이터 로깅을 Phase 1부터 조용히 시작하는 것이 이 로드맵에서 가장 중요한 한 수다 — 모델은 나중에 붙여도, 데이터는 지금부터 쌓아야 한다.

05

국내 수자원 특화 = 세계 우위의 해자

"세계 우위"는 글로벌 강자와 같은 필드에서 정면 승부해서 나오지 않는다. 우리가 압도적으로 유리한 국내 물 인프라 도메인에서 먼저 대체 불가가 된 뒤, 그 엔진을 세계로 수출하는 순서다.

🏛️ 제도가 데이터를 연다

S-Construction 2030: 1,000억+ 공공공사 BIM 전과정 의무화(하천·항만 2024 확대), 건설기준·표준품셈 약 1,079개 디지털화(기계판독).[21] 도메인 특화 학습의 원료가 제도적으로 공급된다.

💧 물 인프라 실적 독점

댐·하천·상하수도·방재 사업의 공정·공기 실적은 국내 사업자만 접근. 이미 시설물 템플릿 33종+댐 9종을 보유 — 여기에 실적 데이터를 결합하면 F3 예측·F4 최적화가 글로벌 범용 툴을 이긴다.

🌊 기후·규제 정합성

우기·홍수·EIA·수문 제약을 공정에 정량 반영(F7). WAMIS 등 국가 수자원 데이터[22]와 연동하면 "한국 물 사업에 딱 맞는 유일한 공정표"라는 포지션이 성립한다.

투트랙 GTM: ① 국내 — 수자원·환경 본부에서 F1·F2·F7로 "쓰기 쉬운 AI 공정표" 표준 장악 → ② 글로벌 — F5 상호운용성으로 해외 물 인프라(ODA·플랜트) 사업에 "K-water 노하우가 학습된 도구"로 진출.

06

과대광고 경계 — 검증에서 기각된 주장들

이 보고서의 신뢰도를 위해, 적대적 검증(주장당 3표, 2표 이상 반박 시 기각)에서 기각된 8건을 명시한다. 로드맵의 근거나 대외 홍보 문구로 이 수치들을 인용하지 말 것. "가능하다"까지만 사실이고, "얼마나 좋아진다"는 대부분 미검증이다.

⚠️ 벤더 자체 발표 수치 (독립 감사 안 됨 — 반드시 출처 귀속)

  • ALICE·McKinsey "공기 최대 20% 단축·상당한 비용절감" → 벤더/컨설팅 공동 보도자료의 상한 한정 자체보고[1]
  • nPlan "세계 최대 75만 공정"·"인간 초과 정확도"·"리스크 80% 예측" → 자체 슈퍼래티브·마케팅
  • Oracle "the only(유일)" → 벤더 포지셔닝(Procore Scheduling 2026 Q1 GA, Planera 등 경쟁 존재)

적대적 검증에서 기각된 강한 주장 (사용 금지)

기각0–3
순수 LLM 스케줄링이 베이스라인 대비 +42.3% / +79.1% / +28.9% 정량 개선을 달성 — CPM 네트워크 구성에서 LLM의 물질적 우월 증거라는 주장.[13]
기각1–2
AI-에이전트 시스템이 계획 시간을 약 95–96% 단축(수십 분→수 분)했다는 주장.[14]
기각0–3
통합 4D/5D 디지털 트윈(BIM+NLP+CV+베이지안+DRL)이 실제 9개월 현장에서 구현·검증되어 견적노동 43%↓, P50–P80 내 정시 완공 등 성과를 냈다는 주장.[19b]
기각0–3
nPlan이 업계 표준을 능가하는 독자 몬테카를로 엔진을 구축해 수만 활동을 수 분 내 확률 예측한다는 주장.[3]

* 함의: 완전 자동 생성·통합 디지털트윈은 아직 개념/프리프린트 단계(Buildings 2024는 "평가 없는 청사진"임을 스스로 명시[19]). 따라서 우리는 검증된 것은 실무형으로, 미검증 강주장은 프런티어로 신중히 배치한다.

07

다음 단계 — 검증이 필요한 질문

  1. 국내 데이터 우위 실증: 검증된 글로벌 기능(ALICE식 최적화·nPlan식 GNN·SBERT 공기추정)을 한국 표준품셈·K-water/댐/하천/상하수도 실적으로 튜닝했을 때 실제로 공기·자원 예측 정확도 우위가 나오는가? (국내 1차 데이터셋 확보 가능성 포함)
  2. 뉴로-심볼릭 MVP 범위: 자연어/BIM→완전 자동 CPM은 대부분 개념 단계인데, "LLM 프런트엔드 + 우리 CPM 엔진"으로 6–12개월 내 실배포 가능한 최소 기능은 어디까지인가?
  3. 물 인프라 CV 검증: 드론/영상 기반 진척 인식(Doxel·Buildots식)을 실제 댐·제방·관로 현장에서 검증한 정확도 사례가 존재하는가? (현 검증에선 물/토목 현장 실증이 부재)
  4. 규제·기후 리스크 정량화 선례: 홍수·가뭄·EIA·우기 제약을 스케줄 리스크 시뮬레이션에 정량 반영한 상용/학술 사례가 있는가? (F7의 차별화 강도를 좌우)
