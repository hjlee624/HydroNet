## 2. 문의 처리 절차 (제안)

1. 사용자가 앱 상단 **🛟 문의** → **📋 진단 정보 복사**.
   - 복사되는 내용: 앱 버전 · 배포 형태 · 생성 시각 · 주소 · 화면 크기 · 브라우저 ·
     현재 모듈 · 프로젝트명 · 공정/연결 수 · 조회전용 여부 · **최근 오류 최대 5건**.
   - **포함되지 않는 것: 전화번호(아이디) · 비밀번호 · 세션 토큰.**
     (`client/src/state/logger.ts` 의 `buildDiagnostics` 는 인증 스토어를 아예 참조하지 않습니다.)
   - **앱이 자동으로 보내지 않습니다.** 사용자가 사내 연락 수단으로 직접 전달합니다.
2. 본부 대표 사용자가 1차 확인 — 접속·권한·저장처럼 문서로 풀리는 건은 그 자리에서 회신.
3. 제품 결함으로 보이면 시스템 담당자에게 진단 정보 그대로 전달.

| 단계 | 목표 기한(제안) | 담당 |
|---|---|---|
| 접수 확인 | 접수 당일 | 본부 대표 사용자 ⬜ |
| 1차 회신(원인 또는 우회 방법) | 3영업일 이내 | 본부 대표 사용자 ⬜ |
| 결함 수정 여부 결정 | 다음 주간 점검 | 시스템 담당자 ⬜ |

> 위 기한은 **아직 합의된 것이 아니라 제안**입니다. 합의 후 날짜와 이름을 채우세요.

## 3. 도입 효과 측정

### 3.1 원칙

- **개인 감시·평가 목적이 아닙니다.** 측정 대상은 사람이 아니라 **업무와 도구**입니다.
- **로그인 횟수·접속 시간·사용 빈도 같은 자동 카운트는 지표로 쓰지 않습니다.**
  많이 켰다고 일이 줄지 않습니다. 저장소에도 그런 사용 계측(텔레메트리) 코드는 없고,
  이번 작업에서도 넣지 않았습니다.
- 지표는 **① 시간 절감 ② 재사용 ③ 중복 입력 감소** 세 갈래로만 봅니다.
- 수집은 자동이 아니라 **아래 표를 사람이 채우는 방식**입니다. 익명 집계로만 보고합니다.

### 3.2 지표 정의

| 코드 | 지표 | 정의 | 수집 방법 |
|---|---|---|---|
| a | **동일 산출물 작성 소요시간** | 같은 결과물을 만드는 데 걸린 분 | `docs/Sequence_본부별_업무예제.md` 의 전/후 기록 |
| b | **재사용률** | 템플릿·기존 사업 복제로 시작한 공정표 ÷ 새로 만든 공정표 | 본부별 집계 ⬜ |
| c | **중복 입력 감소** | 같은 일정을 엑셀에도 다시 적은 건수 | 시범 운영 참여자 자가 기록 ⬜ |

## 4. 성능 · 번들 실측 기록 (F17)

> 이 절만은 **실제 측정값**입니다. 아래 명령을 그대로 다시 돌리면 재현됩니다.

### 4.1 계산 성능 — `npm run smoke:perf`

측정 대상: **막대를 끌 때 프레임마다 도는 계산 1사이클**
(일정(CPM) → 레이아웃 → 화살표 라우팅). 렌더/페인트는 포함하지 않습니다.
스크립트: `client/scripts/perf-smoke.ts` (워밍업 5회 후 30회 반복).

**2026-09-08 · 개발 PC(Windows 10) · Node v24.14.1**

| 공정 수 | 연결 수 | p50 (ms) | p95 (ms) | max (ms) |
|---|---|---|---|---|
| 100 | 95 | 0.5 | 1.0 | 1.3 |
| 500 | 475 | 1.5 | 2.5 | 2.5 |
| 1000 | 950 | 2.8 | 4.6 | 5.2 |

- **회귀 게이트:** 1000공정 p95 > **120ms** 이면 종료코드 1.
- 위 수치는 한 번 돌린 스냅샷이라 실행마다 ±1ms 안팎으로 흔들립니다.
  판단은 **예산 초과 여부**로 하고, 절대값을 인용하지 마세요.
- **사내 PC 실측 칸(사람이 채움):** 기종 ⬜ / CPU ⬜ / RAM ⬜ / 브라우저 ⬜ /
  100 p95 ⬜ / 500 p95 ⬜ / 1000 p95 ⬜ / 측정일 ⬜

### 4.2 번들 크기 — `npm run build && npm run bundle:report`

스크립트: `client/scripts/bundle-report.ts` (`dist/assets` 를 읽어 raw/gzip 산출).

  현재 값은 언제나 `npm run bundle:report` 의 출력이 정답이며, 이 표는 갱신해 주세요.

### 4.3 코드 분할 판단 기준 (지금은 하지 않음)

검토서의 요구는 **“쪼개기 전에 먼저 재라”** 이므로 이번 작업에서는 **분할을 하지 않았습니다.**
아래 조건 중 하나라도 걸릴 때 비로소 착수합니다.

1. `npm run bundle:report` 가 진입 청크 gzip 예산 초과로 실패할 때
2. `npm run smoke:perf` 가 1000공정 p95 예산 초과로 실패할 때
3. 사내 PC 실측(§4.1 빈칸)에서 드래그가 실제로 버벅인다는 보고가 있을 때

착수한다면 가장 손쉬운 후보는 `client/src/export/exporter.ts` 의 정적
`import { jsPDF } from 'jspdf'` 를 동적 `import()` 로 돌리는 것입니다.
다만 `SINGLE=1` 단일 HTML 빌드가 `inlineDynamicImports` 를 쓰므로
`npm run build:single && npm run check:single` 회귀를 반드시 함께 확인해야 합니다.

### 4.4 작은 화면 확인표 (사람이 채움)

브라우저 창을 실제로 줄여서, 그리고 실제 기기에서 확인합니다.
핵심 행동은 **① 공정표 열람 ② AI 검토 의견 확인 ③ 진척 입력** 세 가지입니다.

| 환경 | ① 열람 | ② 검토 | ③ 진척 입력 | 확인자 | 확인일 |
|---|---|---|---|---|---|
| 1366×768 (100%) | ⬜ | ⬜ | ⬜ | ⬜ | ⬜ |
| 1366×768 (125% 확대) | ⬜ | ⬜ | ⬜ | ⬜ | ⬜ |
| 태블릿 (가로) | ⬜ | ⬜ | ⬜ | ⬜ | ⬜ |
| 휴대전화 (세로) | ⬜ | ⬜ | ⬜ | ⬜ | ⬜ |

동작 기준(이번 작업에서 넣은 것):

- 폭 **1100px 이하** — 좌·우 패널이 3단에서 빠지고 **서랍(☰ 공종 구성 / ⚙ 속성)** 으로 열립니다.
  서랍은 도면 **위에 겹쳐** 뜨므로 도면 폭이 줄지 않습니다.
- 폭 **760px 이하** — 편집·취입·계산 같은 데스크톱 전용 컨트롤이 숨고,
  모듈 레일은 **대시보드 · 공정관리 · 진척·실적** 만 남습니다(“편집은 PC에서 하세요” 안내).
- **🛟 문의 · 저장 · AI 검토 · 도면 출력 · 도움말**은 좁은 화면에서도 남습니다.
- 자동 회귀 검증: `npm run mount-test` 의 `[F17 좁은 화면 · 서랍]` 절
  (넓은 화면 3단 유지 = 대조군, 좁은 화면 서랍 전환 = 본 검증).
