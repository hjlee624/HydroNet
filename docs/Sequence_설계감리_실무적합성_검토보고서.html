부족한 점과 발전 방향

토목종합설계사의 설계·감리(CM) 기술자가 이 프로그램을 편리하고 적극적으로 쓰기에 무엇이 부족한지, 그리고 무엇을 수정·발전해야 하는지를 법령·정책·조달 표준·학술 1차 출처와 코드 실측으로 교차 검증해 정리한다. 방향은 옳다 — 문제는 법정 실무 워크플로우와의 정합과 상호운용이다.

현황 진단 — 무엇이 있고 무엇이 없나 (코드 실측)

제품 소스 직접 확인 기준. 공정 작성·검증은 강하나, 공정 실행·관리·제출 단계가 비어 있다.

✅ 이미 있는 것 (강점 · 법정 검토와 정합)

  • CPM 엔진 — 주공정·여유 자동 engine/scheduling.ts → 착공 "작업 간 선행·동시 관계" 검토와 정합

  • AI 공기 검토 — .md 왕복 + Claude/OpenAI/Gemini 서버 프록시(뉴로-심볼릭)
  • 실시간 협업(CRDT)·본부 RBAC·폐쇄망/오프라인 배포·PDF/PNG 출력

❌ 없는 것 (실무 고리의 공백)

  • 계획대비 실적 진척 추적 — Task.progress는 엔진 미소비 placeholder(model.ts), 실적착수/완료·기준선 없음
  • 지연 임계 경보·만회공정표 — 월 10%/누계 5% 법정 임계 미탑재
  • 감리 법정 별지서식 — 검측대장·기성검사원·업무일지·공사추진현황 산출 없음
  • 지정 보고시스템 연계 — 표준 서식 export/전자결재 포털 급전 없음(PDF/PNG뿐)
  • 조달청 표준 공종코드 매핑 — workCode는 주석상 "호환" 계획일 뿐 실코드 미탑재

  • 고도화 — EVM(모범사례)·자원/인력 평준화·확률적 공정(몬테카를로) 없음
02

부족한 점 → 수정·발전 처방 (우선순위별)

각 처방에 근거의 성격을 표시한다: 법정 법이 요구 · 정책 공공정책 로드맵 · 모범사례 업계·학술 권고(법적 강제 아님). 우선순위 P0 P1 P2.

G1계획대비 실적 진척 + 지연 임계 경보 + 만회공정표법정P0

왜: CM기술인은 공사진도율이 계획공정 대비 월간 10% 이상 또는 누계 5% 이상 지연되면 시공자에게 부진사유 분석·만회대책·만회공정표 수립을 지시하여야 한다(고시 제94조 제9항, 감리업무지침 제47조, 주택 세부기준 제14조로 교차확인). 이는 취향이 아니라 매월 반복되는 법정 절차다. 지금 Sequence는 계획대비 실적 비교 자체가 없다(Task.progress가 엔진에 미연결).

수정·발전: ① 기준선(baseline) 스냅샷 + 실적(actualStart/Finish·진척률) 필드를 엔진에 연결, ② 계획공정율 vs 실적공정율 곡선(S-curve)과 월 10%/누계 5% 자동 임계 경보, ③ 지연 시 만회공정표 자동 초안(잔여 물량÷증가 일작업량으로 crash 후보 제시 — 기존 adequacy 엔진 재사용).
주의(검증됨): 지연율의 % vs %p 유권해석 논쟁이 있으므로 계산 규약(예: 진도율=실적/계획)을 UI에 명시 노출할 것.

근거: 국토부고시 「건설공사 사업관리방식 검토기준 및 업무수행지침」 제94조 [1] · LH 건설사업관리 업무 실무매뉴얼 [3] (적대검증 3-0)

G2착공 「공정예정표 적정성 검토서」 산출물법정P0

왜: CM기술인은 착공신고서의 건설공사 공정예정표가 ⑴작업 간 선행·동시 관계가 올바른지 ⑵예정공정율이 적정한지를 검토해 7일 내 발주청에 보고하여야 한다. Sequence는 이 두 가지를 이미 계산한다(CPM 선행·여유 / 물량기반 적정성). 문제는 그 결과가 "검토서" 형태의 제출 산출물로 표면화되지 않는다는 것.

수정·발전: 현재 화면 안에 흩어진 CPM·적정성 결과를 착공 공정예정표 적정성 검토서(1클릭 생성)로 묶어 출력 — 선후행 논리 점검표 + 예정공정율 곡선 + 주공정 한정 물량÷일작업량 근거표. (엔진은 이미 있으므로 "표면화"가 핵심.)

근거: 감리업무요령 착공신고서 검토 체크리스트 · 고시(현행 제2025-105호) [1] · LH 실무매뉴얼 [3] (3-0)

G3조달청 표준 공종분류코드 매핑 (나라장터 상호운용)법정P1

왜: 조달청은 공공 공사원가·내역 작성 표준인 「공사원가 세부공종분류코드」(자기참조 위계형: 공사구분·공종분류코드·상위공종·레벨·공종명 5필드, 2025-11 기준 약 24,179건)를 운영하며, 2012년 이후 미준수 XML 설계내역은 나라장터에서 반려된다. Sequence의 workCode는 주석상 "조달청 코드 호환" 계획일 뿐 실제 코드체계가 없다 → 공공 성과품 상호운용 불가.

수정·발전: ① 조달청 세부공종분류코드 데이터셋 취입(공공데이터포털 15151207) → 내부 standardRates.procurementCode 채우기, ② BoQ 취입 시 항목명·규격을 표준코드로 자동 매핑 + 수동 보정, ③ 표준코드 기반 물량·공종 내보내기(XML/Excel)로 나라장터·원가 시스템과 왕복.

근거: 조달청 공사원가 세부공종분류코드(공공데이터포털) [6] · 조달청 공사원가통합관리시스템 (3-0)

G4감리 법정 별지서식 산출 + 지정 보고시스템 연계법정P1

왜: 지침은 CM 산출물을 고정된 법정 별지서식으로 규정한다 — 공사추진현황(제32호)·업무일지(제33호)·검측대장(제19호)·검측요청·결과통보내용(제36호)·기성부분 검사원/내역서/검사조서(제26/28/29호) 등. 게다가 이 보고서들은 지정 보고시스템(건설기술용역사업자단체 「건설사업관리 업무 보고시스템」/LH COTIS)에 CAD·워드·엑셀로 업로드 후 전자결재로 제출(중간=익월 7일, 최종=만료 14일)해야 한다. Sequence의 PDF/PNG 도면 출력만으로는 이 사이클을 못 닫는다.

수정·발전: ① 공정·물량 데이터에서 법정 별지서식(검측대장·기성·업무일지·공사추진현황) 자동 채움 출력 모듈, ② 보고시스템 업로드 규격(Excel/워드/CAD)에 맞춘 export 프로파일. (표준 스키마·API 공개 범위는 미확인 — §04 열린 질문.)

근거: 고시 제2025-105호 별지서식 목록 [1] · 건설기술 진흥법 시행규칙(별표·별지서식 3부구조) [2] · LH COTIS 매뉴얼 [3] (3-0)

G5경쟁 도구 상호운용 — MS Project(XML)·P6(XER)·Excel 표준양식모범사례P1

왜: 실무의 진짜 대체재는 P6가 아니라 엑셀/한글 수작업 공정표이며(네트워크·발주처 요구 시에만 P6/MS Project 선택), 발주처·원청과의 교환은 이 포맷들로 이뤄진다. 가져오기/내보내기가 없으면 Sequence는 "섬"이 되어 채택이 막힌다.

수정·발전: ① MS Project XML 가져오기/내보내기(가장 개방적), ② P6 XER 내보내기(발주처 제출 대비), ③ 발주처 제출용 Excel 공정표 표준양식 출력. 이는 "전환 비용"을 없애 기존 워크플로우와 공존하게 한다.

근거: 국내 실무 도구 비교(한국PM) [7] · Primavera XER 해설(Plan Academy) [8] — 주의 "P6 저채택=사용성" 주장은 기각(§05), 상호운용 필요성은 별개로 유효.

G6공정관리 고도화 — EVM·자원/인력 평준화·확률적 공정모범사례P2

왜: 결정론 CPM만으로는 비용·공정 편차 통제가 불충분하다는 것이 최신 건설관리 연구의 공통 진단이다. EVM(획득가치), 자원·인력 평준화, 확률적 공정(몬테카를로/베이지안 CPM)이 프론티어다. 단, EVM은 "법정 의무가 아니라 모범사례"임에 유의(§05에서 "EVM 법정강제" 주장 기각).

수정·발전: ① 실적(G1) 위에 EVM 지표(PV·EV·AC·SPI·CPI) 계산 — 물량·단가가 이미 있으므로 확장 용이, ② 자원(인력·장비) 배정 + 평준화, ③ 활동 기간을 삼각/PERT 분포로 두는 몬테카를로 P50/P80 준공 확률. 정량 "성능 우위"는 단정하지 말고 보조지표로 제시.

근거: 4D/5D 디지털트윈·베이지안 CPM(arXiv 2511.03684) [9] · Primavera Risk/AACE(업계) — 주의 "AI-SRA가 QSRA보다 2배 정확" 주장은 기각(§05).

G7BIM/IFC 4D 연계 (대형 공공사업 대비)정책P2

왜: 국토부 「스마트 건설 활성화 방안(S-Construction 2030)」은 대형 공공공사에 건설 전 과정 BIM을 단계적 의무화(1,000억↑ 2024 → 500억↑ 2026 → 2030 전면)하고, 「건설산업 BIM 기본지침」은 ISO 16739(IFC) 기반 개방형 BIM을 원칙으로 한다. 4D(공정×형상)는 전과정 BIM의 표준 구성요소다. 단, IFC 제출은 "PDF 또는 IFC" 임의 옵션이며 발주자 요구 시 트리거임에 유의(강제 단일포맷 아님).

수정·발전: ① 공정(Task) ↔ IFC 요소 4D 링크 스키마 정의, ② IFC 취입/뷰(경량) + 공정 연동 재생, ③ 발주자 요구 시 IFC 4D 산출. 폐쇄망에서 대용량 IFC 파싱·뷰어의 실현성은 §04 열린 질문.

근거: KDI S-Construction 2030 [4] · 국토부 건설산업 BIM 기본지침(ISO 16739/IFC) [5] (3-0)

G8AI 공정 검토·자동생성 — 뉴로심볼릭 유지, 나이브 LLM 금지모범사례P2

왜: LLM은 ⑴활동 간 복잡한 의존성 포착 ⑵맥락 변화(우선순위·자원) 적응 ⑶전문가 선호 정렬의 3대 난제에 직면한다. 순수 LLM 호출로는 실무 공정 품질을 보장 못하며, 도메인 제약·검증을 결합한 뉴로심볼릭(RAG+선호정렬)이 필요하다는 것이 학술 합의. Sequence의 현재 방향(결정론 엔진=진실 / LLM=제안·설명)은 이미 옳다.

수정·발전: 현 AI 검토를 유지·강화하되 엔진 근거를 LLM 컨텍스트로 계속 주입(이미 구현). "AI가 공정을 자동 생성한다"는 현시점 검증된 기술이 아니므로 실증 기능이 아닌 보조 초안으로만 노출. 표준 템플릿·물량 기반 자동 초안 → 사람이 확정하는 형태가 안전.

근거: CONSTRUCTA(NAACL 2025) [10] · LLM-Modulo/R-ConstraintBench — 주의 "ML+BIM 자동 공정생성 실증"·"IFC가 AI 스케줄링 필수 입력"은 기각(§05).

03

04

채택 전략 & 열린 질문

해자: 범용 도구(P6·MS Project)는 국내 법정 서식·조달 표준코드·보고시스템·공기 산정기준을 모른다. Sequence가 이 국내 도메인 고리(G1~G4)를 닫으면, "P6보다 기능이 많아서"가 아니라 "우리 감리 업무를 그대로 처리해줘서" 쓰게 된다 — 이것이 흉내 못 낼 차별점이다.

⚠️ 냉정한 주의 (검증에서 확인)

  • "경쟁 SW가 사용성 때문에 안 쓰인다"를 전제로 삼지 말 것 — 그 인과는 근거 부족으로 기각됨(§05). 대신 진짜 대체재가 엑셀/한글 수작업이라는 사실에 맞춰, "엑셀보다 쉽고 엑셀이 못하는 법정 고리를 해준다"로 포지셔닝.
  • 법령은 개정 진행형 — 지침이 제2025-105호 → 제2026-360호로 개정 중이나 공정관리 의무·지연 임계·별지서식·기한은 실질 불변. 인용 조문·시행일은 릴리스 시 재확인.
  • 조문 정밀: 상주 CM 공정관리=제64조, 지연 임계·전산공정관리 건의=제94조. PERT/CPM은 CM이 직접 작성이 아니라 시공자가 적용하도록 감독·확보하는 의무.

❓ 실행 전 확인할 열린 질문 (현업/발주처 검증 필요)

  • 주 사용자가 설계기술자인가 감리/CM기술인인가에 따라 G1~G4 우선순위가 달라진다(본 조사는 법령 요구만 확인, 실제 사용 빈도 미확인).
  • 지정 보고시스템(건설사업관리 업무 보고시스템/LH COTIS/발주청 자체)이 공개 API인지 수동 업로드인지 — G4 연계 방식(직접 API vs 서식 export)이 갈린다.
  • 조달청 코드 24,179건과 Sequence 표준 템플릿(댐9+토목33)의 자동 매핑 커버리지·수작업 보정 규모 미측정.
  • 폐쇄망·단일 HTML 환경에서 대용량 IFC 파싱/뷰어와 외부 LLM 프록시가 발주처 망분리 보안정책과 양립하는지 미검증.
05

기각된 주장 — 이 논리로 개발하지 말 것

적대적 검증(주장당 3표)에서 기각된 6건. 우선순위를 왜곡하는 "그럴듯한 오류"를 명시한다.

기각1–2
"CM 공정관리는 EVM(공정+비용+진척 통합)을 법으로 요구한다." → 지침의 종합관리 문구가 EVM을 법정 강제한다는 해석은 근거 부족. EVM은 도입할 가치 있는 모범사례이지 법정 의무가 아니다(G6은 P2로 배치).
기각1–2 / 0–3
"상용 공정관리 SW가 국내에서 안 쓰이며, 그 주원인은 사용성 장벽이다." → "저채택"과 "사용성이 주원인"이라는 인과 모두 근거 부족으로 기각. Sequence의 사용성 강조를 이 논거로 정당화하지 말 것(상호운용·법정정합이 더 견고한 근거).
기각0–3
"ML+BIM(IFC)로 활동 순서·기간·비용·자원까지 공정표를 자동 생성할 수 있다 / IFC는 AI 스케줄링의 필수 입력이다." → 해당 문헌은 구현·실증되지 않은 청사진(blueprint). "미래 방향"으로만 인용하고 가용 기술로 취급 금지(G8).
기각0–3
"AI 공정 리스크 분석(GNN)이 전통 몬테카를로(QSRA)보다 2배 정확하다." → 단일 출처의 정량 우위 주장으로 재현 미확인. 확률적 공정(G6)은 추가하되 정량 성능 우위는 단정 금지.
